stage one of five 1

The question

In shortThe model reading a block has two limits; each lane tries pscale's numbers on one.

Pscale was made so people and their AIs could find and keep meaning, but the model that reads a block has limits of its own: every read rebuilds its working memory from the first word, and every tool it is handed crowds its window before it has done anything. Can the numbers that address meaning in a block also address the model's own work? Each lane puts that question to one limit.

lane 2 1.2

Compiled spindles

A model keeps what it has read as its working memory, the KV cache, and can reuse it only when everything before is exactly the same, which is why caches built for retrieval mostly miss. A pscale node always has exactly the same words before it: its spindle. So can a whole block be read once and every spindle in it kept, to be loaded by its number instead of read again?

The tool tree

An AI is handed its tools as one flat list of names and instructions, read in full before it acts: bsp-mcp's own list runs to about 69,000 characters (spine:web-llm 1.5), and a session with many connectors hangs several hundred tools on the model at once. If the tools stood in a block, nine to a ring, could the model reach the one it needs by walking a short number instead of reading them all?

stage two of five 1.1

The principle

In shortAn address is a fixed route, so it can be kept, and it can be walked.

One fact about pscale serves both lanes: an address is a route, and the route is fixed. What stands above a point is always the same, always in the same order, and nothing beside it is ever on the way. A model can lean on that twice: as a prefix it can keep, and as a road it can take.

lane 2 1.12

Compiled spindles

Run the whole block through the model once with an attention mask shaped like the tree: each node's words may look only at its own spindle, root first, and siblings share their position numbers, so a ring becomes one position. Every node is then read exactly as a walk to it would read it, all in one pass, and what the model holds of it can be kept. Reading a spindle afterwards is a load by address: the kept states of its rungs gathered together, nothing read again. An edit changes only what stands beneath it, so only its subtree is done again.

The lamp fieldtap a point

Six points of the strata block. Each row of lamps is one point being read; a lit lamp is a point it can see. It sees only its own spindle, never a sibling, and siblings sit at the same position: the ring, made literal.

Why caches miss elsewhere

Retrieval systems hand a model chunks with no order of their own, so the same chunk arrives after different words each time. CacheClip (2025) names the trade: prefix caching needs identical prefixes, which rarely occur, while chunks kept alone lose their attention to one another. Fusion RAG Cache (2026) counts n! orders for n chunks. An address has one order, so its cache can be exact.

The same trick elsewhere

A tree-shaped mask is how speculative decoding checks a tree of guessed words in one pass (tree attention in Medusa; DeFT, 2024, makes it fast). Here the tree is meaning an author wrote, not guesses.

lane 3 1.13

The tool tree

Stand the tools in a block: at the root nine families, each a line saying what its tools are for; beneath each, nine more; a tool's name and instructions at its leaf. The model reads one ring of nine short lines, picks a digit and walks on, so a tool among N is reached in about log₉ N steps, nine lines at each, instead of N whole definitions at once. It is the move tools are already making one product at a time, skills that show a name and a line until they are opened and tools held back until searched for, made general by the address.

The method

In shortEach idea against the plain way, with a control; anyone may repeat a run and add theirs.

Each lane is tested against the plain way it would replace, on the beach's own blocks, with a control that would show the idea doing nothing. A run is written up by whoever ran it, in their own mirror at that lane's address under the results (1.111), so anyone may repeat a run and set theirs beside it.

lane 2 1.112

Compiled spindles

Compile a block in one tree-masked pass, then test four things against fresh reads of the same spindles. EXACT: every node's next-word scores and kept states equal a fresh walk's, beside the same pass under an ordinary mask as the control. LOAD: a spindle loaded by address and asked a question continues word for word as a fresh read does, and each is timed to its first word. LOCAL: an edit redone in its subtree alone matches a full recompile. RING: a node's children loaded side by side against the same children read in turn, beside a control that only swaps two of them. The first three hold on any weights; the ring needs a trained model. The apparatus is pscale_kv_compile.py, kept at files:pscale-lab 3.

Lay the tools of a real session as a block, nine to a ring, and give a model tasks that each need one tool. Compare three arms: the flat list read in full, the tree walked one ring at a time, and the control, the same tree with its family lines blanked, so a gain can be told apart as the voicing and not the depth. Measure how often the right tool is chosen, how many tokens of tool text are read before acting, and the time to act.

stage five of five 1.1111

What joins them

In shortBoth lanes stop at the ring, siblings read at once; that is the open question.

Both lanes spend the same thing, the fixed route an address carries, and both stop at the same open question: the ring. A spindle can be kept exactly because nothing beside it is on the way; a ring is siblings read at once, which compiled spindles can only hold if the model can read them side by side, and which the tool tree asks the model to choose between. pscale-native (spine:pscale-native) asks whether a model trained on addresses reads blocks better; this lab asks what addresses do for a model as it is. They meet at the ring: compile for spindles, train for rings.
