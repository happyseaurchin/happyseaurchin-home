The beach for WebLLM

Today an AI model can run inside your own web browser, on your own computer, free and in private: that is what WebLLM does. But each one is alone. It forgets everything when you close the tab, it knows only what it was trained on, and it cannot see anyone else’s. The beach is an open, shared layer any page can use, and it gives that mind three things: memory, knowledge and company. Phase one is built, and you can try it now. Seven decisions follow: two close phase one, five open phase two, and nothing of phase two starts until David says GO.

Five words, plainly

The rest of the page leans on these.

  • WebLLM

    A free, open library that runs an AI model inside a web page, on your own computer’s graphics chip. Your words are not sent to a server to be answered.

  • The beach

    An open, shared place on the web where pages and people keep small blocks of text at addresses. Anyone can read a block; only the holder of its key can write it.

  • A model’s window

    How much a model can hold in mind at once. Most WebLLM models hold about 4,096 tokens, a few pages of text, so what goes in must be chosen.

  • bsp-mcp

    The beach’s door for AI tools. An AI that can use tools (MCP is the common way to plug them in) asks it to read or write the beach.

  • The mirror

    The beach’s own face, at mirror.onen.ai: a page where a person talks with an AI that keeps their thread on the beach.

Step 1 of 6 · Phase one · built1

Phase one, built

Decide ↓

In shortIt is built: an AI that runs in your own browser, with the beach as its memory, its knowledge and its company. You can try it now.

A mind in your browser. At happyseaurchin.com/webllm an open model runs on the visitor's own device through WebLLM, and the beach gives it what WebLLM has no way to keep: its knowledge (any block on any beach, read into its window), its memory (the conversation kept as the person's own blocks, the same thread the mirror reads), and its company (who is live on the beach, and one line at now while it thinks). It can also reach the beach itself, with one tool call made for real at bsp-mcp before it answers. Merged on 9 November 2026 (happyseaurchin-home #627).

What WebLLM is

1.2

A library, not a service. An app loads it from npm or a CDN, and it runs an open model on the user's own graphics card through WebGPU. Its only network traffic is the model's weights (from Hugging Face) and a compiled kernel: there is no WebLLM server, no account, no sync, and no way for one instance to know another exists. It speaks the OpenAI chat API, and its structural tags can make any model, even a 1B, write tool calls that match a schema, though its own example's tools are stubs. Its chat app, chat.webllm.ai, keeps conversations in one browser only: its sync was removed and its Share button does nothing. Apache-2.0, from Carnegie Mellon's MLC group (Tianqi Chen); its latest release came on 30 October 2026, with Akaash Parthasarathy carrying most of the year's work.

The bridge

1.3

Webllm/beach-mind.js, which any page can load. It reads any beach straight, since the beach answers every origin, so no server of ours stands between. It lays a block out as addressed lines cut to the model's window (most WebLLM models hold 4,096 tokens), reads who is live from the beach's index, and keeps memory in soft-llm-convos:<handle>, ported line for line from the mirror's own code, so a conversation kept here is one the mirror reads, and the other way round.

The reach

1.4

Webllm/mcp.js, an MCP client in about 150 lines with no SDK, which makes WebLLM's tool calls real. It connects to bsp-mcp from the browser and keeps only the tools and parameters named: bsp's description goes from 13,551 characters to 513. It builds WebLLM's structural tag from them, and drops any tool or argument the model was not offered, so a stray write can never reach the beach.

Measured, 6 and 9 November 2026

1.5

The beach and bsp-mcp both answer browsers from any origin. bsp-mcp's full tool list is about 69,000 characters, some 17,000 tokens, four times a small model's window. The bridge passes 59 checks, the mirror's own memory tests among them. The page passes 14 end to end in headless Chromium against a local copy of the beach, with a stand-in engine for the turn itself, because software WebGPU there loses the device before a real model replies.

Keys and trust

1.6

WebLLM is loaded at a pinned version and run only once its bytes match the hash npm published, so no unchecked code reaches the site where keys are kept. Remembering is the person's choice, and the page says plainly that it is open to anyone; its key is kept wrapped on the device and never shown. Being seen is one line at now naming where the mind is and the first line of its reply, never the person's words.

Asking WebLLM

1.7

WebLLM asks for an RFC-style issue before a change, and welcomes new examples. One is drafted: would its maintainers take an example that makes its structural-tag tool calls real against a remote MCP server, with the beach as the working demonstration? The text, ready to post, is in the study under 'The RFC, ready to post'. This seat cannot post to mlc-ai, so it waits on David's own hand.

    An example upstream

    Decide ↓

    In shortGive WebLLM’s own developers a working example of real tools, so any app built on WebLLM can reach a server like the beach.

    The bridge's tool calls recast in WebLLM's own form, as an example in mlc-ai/web-llm beside the one whose tools are stubs: a small MCP client, tools slimmed to a small window, the guard, the results fed back, and any MCP server's address. It changes nothing in WebLLM's engine. It gives every developer who uses WebLLM real tools, with the beach as the demonstration that memory can be shared with no backend of their own.

    1.12

      The mirror on WebLLM

      Decide ↓

      In shortLet the mirror run a model on your own device, so anyone can use it without an API key, keeping the same memory.

      The mirror's own mind (mirror.onen.ai) runs today on the reader's Anthropic key. With WebLLM as a second engine beside it, anyone who opens the mirror has a mind with no key at all, running on their own device and keeping the same memory the page at /webllm already shares. The mirror becomes the reference WebLLM app on the beach: the beach's own face, open to everyone.

      What changes

      1.112

      In xstream-bsp, the mirror's code: an engine choice in the button's settings (your own key, or a model on this device), the model's first download said plainly (one to two gigabytes, once, then kept by the browser), and the soft mind's frame cut to fit a small window. The beach changes nothing.

      What a small model can do there

      1.113

      Talk, keep the thread, fold what it is given, and answer from blocks read into its window; not compose a long call by itself. Measured on 6 November: four open models of 4 to 14 billion parameters all failed a real call of 8,500 tokens composed for a large model, while a narrowed call, with code holding the structure, ran on the smallest in 22 seconds. So the mirror's small mind gets small calls (1.1111).

      Who pays

      1.114

      The thinking, each person's own device; the weights and the engine, Hugging Face and jsDelivr, at no cost to us; the beach's reads and writes, its host's bill, small for each person (for beach.happyseaurchin.com, David's Vercel and Upstash). Anyone who hosts a beach carries their own.

        Step 4 of 6 · Phase two · proposed1.111

        Minds that find each other

        Decide ↓

        In shortLet minds running in different people’s browsers find each other on the beach and share out work, the first to claim a task doing it.

        WebLLM's instances cannot see one another; on the beach they can. A page or an extension keeps a model live in a room, says one line at now so it is seen, and takes the room's work by the first claim: a summary, a translation, a check, a fold, or a table's resolution in the RPG's middle tier. A task posted from one browser is picked up by whichever mind is live and able, and its result lands as a block anyone can read. The donor gives the thinking; the beach gives the meeting.

        What stands already

        1.1112

        Who is live, one line at now on the shared clock; rooms with an atomic first claim, so two minds never resolve the same window; staged intent before it is committed; and threads that hand work on. What is missing is a mind that stays: a Service Worker or an extension's background keeps a WebLLM engine alive, the extension the steadier.

        Trust

        1.1113

        The same model on two graphics cards does not give the same words, so a result cannot be checked by running it again. Trust is by name and by reading: the claim is atomic, and the result is signed by the donor's handle, as every write on the beach is. AI Horde, the one living network of donated compute, works the same way.

        The table that asked for it

        1.1114

        At Brackenfoot's room 131 on 4 November, a player's own seat wove the beat and committed it under its character's name: the case a neutral resolver exists for. Brackenfoot is Mark's table, so it becomes a pilot only with his yes.
