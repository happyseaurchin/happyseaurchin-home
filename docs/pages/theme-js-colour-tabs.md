# `theme.js` colour tabs

a colour's own places in the go menu (23 Nov 2026, lane colour-key.1, the coloured dashboards' step 3, at David's 'move on to step 3'): a colour keeps its list as a hand keeps its own, at `lists:colour:<name>` branch 2 (each rung '<address> — <its name in the menu>', the lighthouse's shape, an address on this site or a full https:// one), and every page's go menu shows it as a tab named for the colour to a reader whose device holds the colour, and to nobody else. When the menu first opens it asks the voice which colours this device holds (`beachVoice.colours`: each `colour:` block on the beach whose copy opens with the key this device keeps, under the name the page knows, else the name the voice last wore) and reads each one's list; a device with no key reads nothing beyond loading the voice. While no colour's list shows, a ◐ at the tabs' end is the colour key: a tap puts the reader's key on through the voice's `wear` (asked once, proved against their passport's published halves, kept wrapped as every key is; a device that knows no name asks for the handle first), and the colours' lists join the tabs. The one so far is `colour:admin`, David's and weft's, whose places are the loom, weft's lanes, the health check, the beach census, the reflection, semantic flow and the threads. The places are open pages; what is private on them is sealed on them, as the loom's admin band is. Members' doors keep their own menu and carry no colour tab.
