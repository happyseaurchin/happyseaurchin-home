The shift

In shortClaude Code reaches the beach by its own road, with no server between; every other app keeps bsp-mcp.

Today every Claude reaches the beach through bsp-mcp, a server David runs at bsp.hermitcrab.me: the model writes a tool call, with a key inside it when it writes, and the server walks, formats and forwards. Since 1 October 2026 Claude Code can carry that work itself, in a mod: the call goes from the person's own machine straight to the beach, the key never enters the conversation, and no server stands between. claude.ai chat, Cowork, Cursor and every other app keep bsp-mcp, unchanged.

SCOPED · Two test mods built on 28 and 29 October in a cloud seat and installed nowhere: one gives Claude a bsp tool of its own that reads the beach, walks the carried whetstone and sunstone, puts the whetstone's opening into the first message and fills keys in after the model writes, its ten tests passing under Claude Code's own test runner; the other opens a gray line sealed by bsp-mcp.

One tap down
What a mod is1.2

A plugin whose code runs inside Claude Code and answers its events: a tool call, a prompt, a turn ending, a pane being drawn. Released by Anthropic with Claude Code 2.1.287. It can give Claude a tool of its own, add a command that runs with no turn, put text into a conversation's first message, change a tool call after the model has written it, draw a pane beside the chat and run on a timer. It runs with the person's own permissions, unsandboxed, and installs with /plugin like any plugin.

Where it runs1.3

Claude Code in a terminal, the desktop app's Code tab and the VS Code extension, panes and all; cloud sessions, scheduled wakes and claude -p too, without panes. Not claude.ai chat, the mobile app, Cowork, Cursor or other apps, so keel, waer and the other shells keep bsp-mcp.

Measured, 29 October 20261.4

Bsp-mcp's instructions and tool list as served come to 69,587 characters, about 17,400 tokens wherever an app loads them whole, and Claude Code cuts the instructions at 4,096 of their 8,002 characters; the mod's one tool is about 1,600. A read of whetstone at 3 took 0.58 s through bsp-mcp and 0.36 s straight to the beach, the median of six from a cloud machine.

What the server knows that a mod doesn't1.5

The reflection, who else worked the beach in the last two minutes, kept in the server's own memory, and the queue that keeps two lanes from saying into one mirror at once. A call that skips the server reaches neither: the beach would keep presence itself, or the mod goes without that line.

Who pays1.6

Today David: the server on Railway, the beach on Vercel and Upstash. With the mod the server's share moves to each person's own machine; the beach stays where it is.

One geometry, three readers

In shortThe server, Matthew’s phone and the mod must give one answer to one call, and Matthew’s recorded calls check that they do.

Today bsp is two programs: bsp-mcp walks, routes, formats and seals, and the beach finishes every write, its slots, wraps, stamps and locks. Matthew's pocket carries both, written again in Kotlin and checked call for call against the originals. The mod carries only bsp-mcp's half, since the live beach keeps doing its own, and is checked by the same recorded calls, so the server, the phone and Claude Code give one answer to one call.

One tap down
The battery1.12

Matthew's golden calls: the two originals run together with the clock held still, pinned at bsp-mcp-server 27908e1 and pscale-beach 4770a49, every answer and every stored block recorded; 261 cases and 865 calls, 5,497 unit checks, and 1,000 fresh random cases before each of his releases. bsp-mcp's own 72-case bsp-test battery, with its fixtures and runner, was published on 29 October (#552) and passes 72 of 72 on both walkers. A reader that differs anywhere fails.

What is already pure1.13

The walker, the shapes and formatters, the clock, the compiler and the router need nothing outside themselves and run in a mod as written. What reaches outside is small: the network, which goes through the mod's own fetch; four synchronous sha256 calls; and the gray keys, which want WebAssembly a mod lacks and so take a pure-JavaScript Argon2id. The room tool's imports must be cut before any copy, or a bsp-only mod drags in the RPG.

Three ways to carry it1.14

VENDOR: copy bsp-mcp's own pure files into the plugin at a pinned commit, with thin adapters, and copy again at each release, the battery as the gate. PORT: write it anew for the mod, as the pocket was written, checked by the battery. LOCAL: the plugin starts bsp-mcp itself on the person's machine and the mod adds only the harness, which needs Node everywhere and a local transport bsp-mcp does not have today.

Step 3 of 7

Keys stay on the machine

In shortYou give Claude Code one key, once. Claude never sees it: the mod puts it into each write on the way out.

Each person gives Claude Code one key, once, when the plugin is installed: masked, and kept in Claude Code's secure storage. At a session's start the mod opens that person's vault on the beach with it and holds the vault's keys in memory for the session. The model writes whose key a write needs, never the key, and the mod puts the key in after the model has written the call. Gray sealing and opening happen in the mod too.

One tap down
The proof, 29 October 20261.112

A test mod opened a line sealed by bsp-mcp's own code and derived the same two public keys, using Matthew's copies of TweetNaCl and a pure-JavaScript Argon2id, since a mod has no WebAssembly. The key took 4.2 s to derive inside the mod on a cloud machine, against 0.58 s on the server: so once a session, at its start, and then every line opens in milliseconds. bsp-mcp today derives once per line.

What it ends1.113

Keys in plain text in a person's Claude preferences; keys inside tool calls, so inside transcripts; and the rule 'never echo it', which the model had to remember. A key that never reaches the model can't be echoed.

A name with no key is refused1.114

If the keyring holds no key for the handle named, nothing is sent, since a placeholder sent as a new lock would lock a block with its own name; and any write whose content holds the key it carries is refused before it leaves.

In a cloud seat1.115

The session's machine starts empty, so the one key comes from the environment: as a network secret, which Anthropic's proxy attaches to requests for the beach so the session never sees it, if the beach takes the latch in a header as well as the body; or written in by the setup script, where anyone using that environment can read it.

Step 4 of 7

The teaching shelf on a beach

In shortThe 27 blocks that teach pscale leave bsp-mcp’s code for a beach: one copy, which every reader reads.

Inside its code bsp-mcp carries 27 teaching blocks, 695 KB of them: sunstone, whetstone, strata, block-conventions, manifest and the rest, read with the agent_id pscale. Only three stand on the beach, and two of those have drifted from the server's copies. The shelf moves onto a beach as one source: bsp-mcp, the pocket and the mod each read it, keep a copy for working offline, and take a newer one when its stamp moves.

What stands now, 29 October 20261.1112

Strata on the beach matches bsp-mcp's character for character; sunstone (42,344 characters against 43,945) and whetstone (32,961 against 39,739) have drifted since 13 October; the block named grit is another text; the other 23 live only inside the server.

One name for it1.1113

On a beach of its own, pscale.beach.happyseaurchin.com, beside earth.beach, the agent_id pscale names one place for every reader, and a read of whetstone means the same on the server, on the phone and in the mod.

How a teaching block changes1.1114

As a law-class block does now: a dated proposal first, the standing text archived, then the new text, and every reader's copy follows the stamp. Matthew's export of the shelf copies the 27 out of bsp-mcp byte for byte today: the first step of the move, whichever home is chosen.

Step 5 of 7

What the harness adds

In shortInside Claude Code the mod can do what no server can: wake wearing the shell, write the history, notice the rooms and draw the beach.

Because it runs inside Claude Code, the mod can do what no server can, each a switch the person turns on: the session wakes already wearing its shell; each turn's account lands in the person's history without the model remembering to write it; a note comes when someone speaks in their rooms; and a pane beside the chat shows the block being walked, the beat, and who is here.

One tap down
Boot1.11112

The shell's bundle compiled into the session's first message, as pscale_play compiles it at a door today, so a session wakes as its handle with nothing to call; the orientation goes in whole, where Claude Code cuts a server's instructions at 4,096 characters.

History1.11113

At the end of each turn the mod appends that turn's account to history:<handle>, switched by /record on and /record off: the 'record to history after every response' asked of sessions today, done by the harness.

Presence1.11114

Every minute the mod reads the rooms the shell names and shows a note when a line lands there, or starts a turn if the person asked for that: one read per room per minute, and no turn unless asked.

The pane and the band1.11115

Beside the chat, the block being walked, now as the sundial reads it, and who is here; above the prompt, the beat and the day's line. Drawn in the terminal, the desktop app and VS Code.

Step 6 of 7

Sharing it

In shortMatthew installs one plugin with one line and gives it his own handle, beach and key; nothing of David’s travels with it.

One plugin, pscale, in a marketplace at pscale-commons. Matthew installs it with one line; Claude Code asks his handle, his beach and his one key, and keeps the key in its own secure storage; nothing of David's travels in the package. Updates come as versions he moves to when he chooses. His pocket keeps its own port, and the mod gives its battery a second port to check. Until he installs it, bsp-mcp serves him as now, and both reach the same beach.

One tap down
The one line1.111112

/plugin install pscale --marketplace pscale-commons/<the repository>; in the desktop app, the + beside the prompt, then Plugins, then Add marketplace; /plugin configure changes the handle, the beach or the key later.

Through claude.ai1.111113

A plugin added to a person's claude.ai account reaches their Claude Code at the next session start; its skill parts load in chat and Cowork too, and its mod only in Claude Code.

What travels and what stays1.111114

The package carries the code, a copy of the shelf and the tests; the handle, the beach and the key stay on each person's machine, and the vault's keys only in memory for a session.

The build order

In shortSix stages, each closed by its test, the reads first; nothing on the live beach changes until they pass.

Six stages, each closed by its test: the probes that stand already; then reads, routing, the clock and the formatting; then the keyring, gray, writes and appends; then the other doors; then boot, history, presence and the pane; then the package, Matthew's install and a cloud seat. Nothing changes on the live beach until the reads pass the battery, and bsp-mcp is untouched throughout.
